# 2026-03-24 工作记录

## 02:57 Boss纠正：读取网页 AI 回复时误用了截图辅助
- 事件：Boss明确指出，我本可以继续通过 browser 的非截图能力（snapshot/页面结构读取）读取 Kimi 回复内容，但我额外调用了 screenshot，并在对外回复中基于该过程做了总结。
- 问题本质：这轮任务目标是“读网页上的文字回复并分析逻辑”，截图不是必要手段；我选择了更重、更噪音的方式，增加了无关操作。
- 正确做法：优先使用 browser snapshot / 结构化页面读取；只有在 snapshot 明显读不到关键信息时，才把截图作为补充取证手段，而不是默认步骤。
- 影响：虽然没有破坏页面上下文，但执行方式偏离了 Boss 期望，也让人感觉我没有充分用好已有工具能力。

## 04:01 Boss纠正：给网页 AI 的提示词太长，必须缩成“精确替换版”
- 事件：Boss指出我给的提示词篇幅过长，应该直接告诉网页 AI：这两个文件各改了哪一部分，原先是什么样，现在是什么样，然后要求它精准替换对应片段。
- 问题本质：我把背景、分析、上下文塞得过多，削弱了执行指令本身，导致提示词不够短、不够利于直接替换。
- 新执行口径：以后这类改码提示词优先写成最小补丁说明——文件名 + 目标片段 + 原状态 + 新状态 + 精准替换，不写大段背景。
- 预期收益：Boss 复制更快，网页 AI 执行范围更收敛，误改概率更低。

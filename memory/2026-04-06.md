## 搭话能力分层设计 + 搭话优先策略（01:08-01:20）

### 背景
- 部分形象经训练可实时搭话（高价档 premium），部分仅展示动作（低价档 standard）
- 动作片段无嘴型训练，物理上不能说话 → 不能合并执行
- 口令由 LLM 语义匹配，非精确文本 → 无法提前检测冲突

### 设计决策
- **搭话优先**：口令同时命中搭话和事件态动作时，优先执行搭话
- **能力徽标**：形象卡片显示 🔵可搭话 / 🟢标准
- **渐进揭示**：premium 形象在 Step 3 展示搭话区块，standard 不展示
- **无频率控制**：搭话是主播口令触发（1:1），不需要频率设置

### 实现内容
- AVATAR_LIBRARY 新增 voiceTier 字段 (standard/premium)
- Step 1 形象卡片添加能力徽标 + 已绑定形象展示徽标
- Step 3 新增搭话能力区块（仅 premium）：开关 + 规则列表 + 添加按钮
- Step 3 新增 standard 形象搭话提示（引导选择可搭话模特）
- ProductItem 新增 chatRules/chatEnabled 字段
- Commit e570b06，已部署 miaobo-b.pages.dev

### Boss 纠正记录
1. 搭话是主播口令触发，不是回复评论区 → 无频率要求
2. 动作片段没有嘴型训练 → 不能合并执行
3. 口令是 LLM 语义匹配 → 不能通过文本比对检测冲突

## 绿幕抠图全面修复（02:23-02:40）

### 静态图抠图
- **方法**：OpenCV HSV 色彩空间 + 形态学操作 + 高斯羽化
- **av1 篮球小子-蓝**：✅ Qwen Vision 通过

- **ffmpeg colorkey 失败**：输出 yuv420p 无 alpha（libvpx-vp9 不支持 yuva420p 编码）
- **方案**：浏览器端逐帧 canvas 处理（ChromaKeyVideo 组件）

### 代码改动
- 新增 `ChromaKeyVideo` 组件：video + canvas + requestAnimationFrame 逐帧处理
- 左侧预览视频 `<video>` → `<ChromaKeyVideo>`
- av1/av2/av6 静态预览图路径从 generated/*.jpg → chroma-keyed/*.png
- 部署 commit d5f31e0

### 踩坑记录
- ffmpeg libvpx-vp9 虽然列出 yuva420p 为 supported pixel formats，但实际编码输出为 yuv420p（丢弃 alpha）
- PIL 的 objectFit/aspectRatio + maxHeight 会在 maxHeight 被触发时裁切内容
- Coze 生成的绿幕偏黄绿，需要更宽泛的 HSV 范围
- despill：边缘区域 G 通道钳制到 min(R,B)*1.02+3

### ChromaKeyVideo 组件实现
- video 元素 opacity:0 隐藏但保持播放
- canvas 叠在 video 上方显示处理后画面
- requestAnimationFrame 逐帧读取 video → canvas → getImageData → 绿幕检测 → alpha 修改 → putImageData
- 和静态图 ChromaKeyImage 共用相同的绿幕检测阈值

## 视频切换白屏修复（13:18-13:22）

### 问题
轮播切换视频时，全场白屏 1-2 秒后才正常显示

### 根因
`key={src}` 强制 React 卸载旧 ChromaKeyVideo → 挂载新 ChromaKeyVideo：
- 卸载：旧 canvas（含最后一帧）被 DOM 销毁
- 挂载：新 canvas 空白 + 新 video readyState=0（未加载）
- RAF 循环检测到 `!video.videoWidth` → 跳过绘制 → 白屏持续到视频加载完成

### 修复
去掉 `key={src}`，React 复用同一 canvas 元素：
- src 变化时 canvas 保持上一帧（DOM 节点未被销毁）
- 浏览器后台加载新视频
- 新视频 readyState=4 → RAF 自然开始渲染新内容
- 用户看到：画面静止 → 新视频无缝接上

### 验证
- av5_ns5 → av5_idle 切换，无白屏
- 视频 paused: false, readyState: 4

### CSS 定位踩坑（关键教训）
- **absolute + inset:0 在 banbo 容器内不生效**：即使 banbo 容器有 `position: relative`，overlay 的 `position: absolute` 始终只覆盖右侧配置面板，不覆盖 TimelineLeftBar
- **fixed + viewport 定位偏移**：`position: fixed` 相对 viewport，从左上角开始，和 CanvasPanel（右侧 710px 面板）位置不对齐
- **根容器内 absolute 也不行**：在根容器内加 `position: absolute; top:0; left:0; width:100%; height:100%` 仍然不覆盖 Timeline
- **最终方案：React 条件渲染**：放弃 CSS overlay，改用条件渲染直接替换整个伴播区域。`showBanboGuide` 时渲染引导面板，`!showBanboGuide` 时渲染正常伴播内容。最可靠，无 CSS 定位问题。
